# TEXTRIS 테마 표현 고도화 사전 점검

점검 시작: 2026-10-13. 최종 보고: 2026-10-14, Asia/Seoul. 기준: v1.2.1, HEAD `7b0a55c`.
요청: 각 테마를 텍스트로 가능한 수준까지 고도화하기 전에 현재 상태와 개선 방향 보고.
판정: **기존 기능은 확인됐으며, 구도·테마별 조작 연출·상태 반응·표현 기법을 보강할 여지가 크다.**
이번 작업은 점검과 제안이다. 후속 요청에 따라 향후2보드 화면의예정설계를
`../theme-enhancement-layout-design.md`, `spec.md`, `designs.md`에 반영했다.
제품 코드·현재 게임/저장 계약·버전·배포는 변경하지 않았다.

  연출이 있다. 예전의 다른5테마 성취 형상 단일화 문제는 이미 수정됐다.
- 기반: Braille 2×4 서브셀, 깊이 합성, 테마 팔레트, 계층 캐시, 유한 수명·우선순위,
  주 연출1개/국소8개, Unicode/ASCII/모노 및 섬광·흔들림 설정.
- 갤러리19배경/25효과는 실제 게임의 테마 연출과 다른 경로다. 갤러리 품질이 곧
  게임 중 해당 효과 적용을 의미하지 않는다.

## 우선 해결할 공통 항목

### T-01 — 최소 창에서 테마 형상이 거의 사라짐 / High

- 실제: `game_layout()`은64×28의 렌더 가능1764셀 중98.7%를 보호한다.
  배경에 남는 영역은23셀이다. 동일 시각의 배경 셀은 대성당2, 사이버펑크8, 우주3,
  불꽃/CRT/모노0이었다. 값은 해당 시각 표본이며 모든 시각을 뜻하지 않는다.
- 기대: 보드/HUD 가독성을 유지하면서 최소 창에서도 테마를 형태로 식별한다.
- 제안: 크기별 전용 구도, HUD 실제 정보 영역과 불투명 바탕의 정교한 보호,
  테두리·상하 여백에 축약한 테마 문양과 국소 효과. 작은 창에서는 실제 남은 공간에 맞춰 생성한다.
- 재검증: 64×28/80×30/120×40/160×50 각각에서 형태 인지, HUD 보호, 모든 성취의 가시성을 확인한다.

### T-02 — 조작 효과가 대성당 구현을 공유 / High

- 실제: 다른5테마의 `ThemeScene.render()`도 `CathedralScene.local_effect()`를 호출한다.
  드롭·착지는 같은 세로선/타원, 회전·홀드 등은 같은 양옆 기호를 사용한다.
- 제안: 공통 좌표·수명·예산은 유지하고 테마별 조작 표현을 분리한다.
  이동/회전/홀드/드롭/착지 각각에 다른 방향성과 모양을 부여한다.
- 재검증: 같은 입력·블록·위상에서6테마의 형태가 구별되고 실패 조작에는 효과가 없으며,
  연속 키 입력에서도 효과 수와 수명이 제한되는지 확인한다.

### T-03 — 위험·피버·연속 성취의 배경 반응이 제한됨 / High

- 실제: 위험은 공통 테두리·DANGER, 피버는 공통 문구 중심이다.
  테마 장면은 danger/fever 상태를 직접 받지 않는다. 콤보는주 연출 power에 일부 반영되며
  Tetris/T-spin은 같은bloom 유형, 일반1~3줄 삭제는 같은clear 유형이다.
- 제안: 위험 진입/회복, combo 단계, B2B, fever 시작/유지/종료에 대한 시각 상태를
  표시 전용 데이터로 전달한다. T-spin의 회전 운동과 Tetris의 일제 분출을 구별한다.
- 재검증: 동일 게임 상태의 시각 차이·상태 복귀·이벤트 우선순위·리플레이 불변을 확인한다.

### T-04 — 같은 우선순위 연속 사건의 최신 의미가 유지되지 않음 / Medium

- 재현: Tetris 직후0.1초에 다른 행의T-spin을 전달하면 기존TETRIS label과18~21행이
  남고power만1.08로 오른다. `ArtDirector.trigger()`의 동일/낮은 우선순위 병합 동작이다.
- 제안: 높은 우선순위 연출을 유지하면서 같은 계열의 최신label/coords를 반영하거나
  제한된 후속 연출로 연결한다. 새 사건이 이전 삭제 위치에서만 보이는 경우를 줄인다.
- 재검증: 빠른 연속 삭제, T-spin→Tetris, 레벨업 동시 사건, All clear·승패 우선순위.

### T-05 — ASCII/모노와 품질 하향의 표현·비용 효율 / Medium

- 실제: 서브셀의ASCII 폴백은대부분`:`에 합쳐진다. 다섯테마의 주요 곡선 표본 수는
  고정이고quality는 주로 미세 입자에 적용된다. 현재 줄/윤곽 중심 표현이 많다.
- 제안: 선 방향·면적 점유·명암에 따라ASCII/블록/음영 문자를 선택한다.
  모노는 윤곽 굵기·교차 해칭·디더링으로 형태를 구별한다. 품질 단계는 곡선 표본 수,
  레이어·잔상·입자 예산에도 반영하고, 보이지 않는 형상은 생성 전에 제외한다.
- 재검증: 색상 없이도 테마/사건 인지, 저품질의 비용 감소, 최종 출력 포함 p95/입력 응답성.

### T-06 — 대성당 성취의 의미·강도 반영 편차 / High

- 실제: 동일 시간·위상·강도를 맞춘 섬광OFF 비교에서 대성당은6개 성취가5개 형상으로
  나타났다. 올 클리어(ascension)와 승리(victory)가 같은 형상을 사용한다.
  일반삭제/종료/레벨업·시작은 intensity와power를 바꿔도 형상이 같았고,
  강한삭제·올 클리어의coords 변화도 형상에 반영되지 않았다.
  다른5테마는 이 검사에서6종 형상과 강도·power 변화가 구별됐다.
- 제안: 대성당도 의미별 형상·삭제 위치·강도 변화가 전달되도록 같은 공통 계약에 맞춘다.
  올 클리어는 삭제 위치에서 상승하는 광막, 승리는 장미창과 아치의 완결 동작으로 구별한다.
- 재검증: 모든6테마를 대상으로 같은 위상에서6종 의미, 강도/power/행 좌표,
  섬광OFF와모노에서 차이가 남는지 확인한다. 현재 성취 단위 테스트는대성당을 제외한다.

잔상·발광·반사·열기 등은 문자 밀도/명암/좌표/깊이로 만드는 표현이다.
터미널의 실제 광학 블러·픽셀 셰이더·임의 알파 합성으로 보장하지 않는다.
장면의 좌우 구조·거리층·속도를 다양화하고 도입→확장→정점→감쇠의 시간 흐름을 만든다.
갤러리의 효과는 테마·게임 사건에 맞는 부분을 재사용하고 사용 여부를 실제 게임 경로에서 확인한다.

## 성능과 구현 순서 제안

120×40, 테마별240프레임의App.draw p95(ms): 대성당15.088, 사이버펑크10.519,
우주10.084, 불꽃11.572, CRT8.632, 모노7.901. **터미널 출력·물리 입력 제외**이며
공유 호스트의 일회 측정이다. 대성당은16.7ms 목표에 근접하고 일부 긴 표본도 있어
현재 값으로 실제60FPS나 고도화 후 성능을 보장하지 않는다.

1. 작은 창 구도·보호 영역·문자 명암·상태/사건 계약을 먼저 설계한다.
   향후2보드를수용하도록공용배경과플레이어별viewport·정보·효과 영역을분리한다.
2. 국소 효과와 상태 반응을6테마 모두 같은 수준으로 연결한다.
3. 테마별 거리층·면 명암·고유 움직임·성취 시간 흐름을 적용한다.
4. 메뉴/준비/결과/쇼케이스/갤러리까지 같은 미술 언어로 정리한다.
5. 실제 출력 포함 성능, 접근성 설정, 연속 사건, ASCII/모노·작은 창,
   게임 난수·저장·리플레이 불변을 검증한 후 패키징한다.

이번 사전 점검에서 추가 보안 감사·음원 재제작·제품 수정·커밋·태그·릴리스는 수행하지 않았다.
새로 확인된 검사 도구의 인코딩 문제도 다음 구현 시 설계·테스트와 함께 처리할 대상이다.
