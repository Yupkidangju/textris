# 텍스트 효과 2차 고도화와 8개 테마

작성: 2026-10-15. 기준: 사용자 추가 구현 요청, spec.md, designs.md, D3D 구현·코딩 표준.
현재 기반 v1.3.0, 목표 릴리스 v1.4.0.

## 확정 범위

기존 여섯 테마의 시간에 따른 세부 표현을 강화하고 `abyss`(Bioluminescent abyss),
`aurora`(Aurora snowfield)를 추가한다. 이름과 시각 방향은 세부 지정이 없어 기존 장면과의
차별성을 기준으로 이번 구현에서 선택했다.

| 테마 | 강화할 문자 표현 |
| --- | --- |
| cathedral | 이동하는 채광, 아치의 빛 점묘, 향 연기와 종의 여운 |
| cyberpunk | 계단식 데이터 흐름, 끊기는 네온 반사, 회로 조작 잔상 |
| space | 앞뒤 거리의 유성 꼬리, 궤도 표식, 중력파 여운 |
| fire | 상승 기류의 재와 열기, 냉각되는 불씨와 후광 |
| crt | 주사선과 신호 팁의 잔광, 벡터 에코, 신호 수렴 |
| mono | 이동하는 판화 해칭, 선 끝의 잉크 점, 기하학적 여운 |
| abyss | 수면 광선/물결, 해파리와 촉수, 해저 능선, 기포와 발광 플랑크톤 |
| aurora | 깊이가 다른 오로라 커튼, 설산/빙면 반사, 눈송이와 결정 가지 |

큰 장면은 120×40 여백에 배치하고 64×28에서는 축약 문양과 상단 띠로 정체성을 유지한다.
새 테마도 메뉴/Profiles/CLI/게임/감상 화면에서 선택·저장된다. 기존 테마 ID, 저장 version 1,
게임·난수·리플레이와 두 보드 viewport 계약을 보존한다. 실제 배틀/AI/온라인은 후속 범위다.

## 구현 계약

- 새 환경은 별도 작은 모듈과 기존 합성 경로에서 구현한다. 시간 양자화 캐시를 사용하고
  누적 프레임·파티클 목록을 만들지 않는다.
- 조작 잔상은 cue 수명에서 과거 위치를 계산한다. 최대 2개의 희미한 에코만 허용하며
  기존 국소 8개/brush 예산을 지킨다. intensity 0/만료 cue는 비표시다.
- 새 테마는 clear/bloom/ascension/victory/eclipse/awakening별 고유 형상과 T-spin 변주를
  갖는다. 삭제 행·강도·flash OFF·플레이어별 영역을 준수한다.
- 품질 단계는 표본·거리층·입자 수를 줄인다. ASCII는 7비트, 모노는 형태/밀도로 식별한다.
  보드/HUD/모달과 다른 플레이어의 보호 영역은 그리지 않는다.
- `themes.py`를 시각 테마의 단일 목록으로 사용한다. 원본 음악 카탈로그는 기존 6테마와
  Classic 26곡/30효과음 그대로 유지한다. abyss → space, aurora → mono 음악을 연결한다.
  게임은 연결된 3곡과 Classic 8곡을 기존 1:1 셔플로 재생한다. 감상에서도 3곡을 제공하고
  원래 곡 분류를 표시한다. 신규 작곡으로 표기하지 않는다.
- CPU 목표는 120×40 p95 16.7ms, Windows 실제 출력 비용은 별도 기록한다.
  v1.3.0 fire/CRT 출력 병목을 감안해 비용을 측정하고 필요 시 상세 표현을 조절한다.

## 작업 순서와 소유 경계

subagent-driven-development와 dispatching-parallel-agents를 적용한다. 깨끗한 기존 체크아웃의
`codex/text-effects-eight-themes` 브랜치에서 작업해 로컬 Windows 의존성과 제작 자료를 재사용한다.

1. 주 작업자: 문서, themes/scenes/storage/audio/감상 UI/팔레트/번역 통합과 회귀.
2. 장면 작업자: theme_art/theme_surfaces와 새 환경 모듈, 새 테마 배경·6성취, 기존 환경 강화.
3. 조작 작업자: theme_actions와 해당 회귀, 8테마 모양과 제한된 잔상.
4. 독립 검토와 결함 수정, 실제 캡처의 형태·대비·배치 검토.
5. 전체 회귀, Windows 버퍼/입력/음악/부하 측정, 패키징·EXE·태그 푸시.
   이전 패키징·태그 푸시 요청의 승인을 이어 적용한다.

| 경계 사전 점검 | 생산 → 소비 | 결정 |
| --- | --- | --- |
| 1→2/3 | themes.THEMES | 기존 6개 뒤 abyss, aurora; 기존 ID/순서 유지 |
| 2→합성 | ThemeScene.render | 기존 인자/반환 유지, 파일 소유 분리 |
| 3→2 | render_local/render_state | 호출 계약 변경 없음, 예산 내 추가 |
| 1→오디오 | visual ID → music ID | 중앙 매핑; 엄격 카탈로그 검사는 원본 6테마 기준 |
| 각 작업 내부 | 코드·검사·문서 | 저장/게임 변경 없음; 원음 변경 없음 |

## 검증과 완료 게이트

- 8테마 선택 순환/저장/CLI, 감상 10모음과 음악 매핑, 26곡 카탈로그 검사.
- 8테마 × 6성취 × 4크기 × Unicode/ASCII/모노, 실제 게임 이벤트 경로.
- 최소 창, flash OFF/낮은 품질/만료/정지, P1/P2 격리와 RNG·리플레이 불변.
- 시간 변화·모양 차이·그림 검토, Windows 실제 버퍼·입력·종료.
- 전체 단위 검사/compileall, CPU 및 Windows 출력 부하, 패키지 자원·실행.
- 측정과 직접 시각·청취 확인 범위를 구분한다. OS 볼륨·음소거는 변경하지 않는다.

## 진행 기록

- 설계와 인터페이스 사전 점검 완료. 코드 변경 전에 작성했다.
- 작업 1/2/3 구현 완료. 통합·장면·조작 회귀와 독립 통합/전체 코드 검토를 완료했다.
- 발견한 검증 도구의 고정 모음 인덱스를 동적 목록 기준으로 수정했고 import 수명도 수정했다.
- 전체 304개 검사와 Windows 테마144/입력7/감상4조건 통과. skip 및 실행 범위는 검증 문서 참조.
- 최종 전체 306개(296통과/10skip), CPU/네이티브 재측정과 로컬 패키지·실제 EXE 검증 완료.
  일부 네이티브 출력 부하의 60FPS 미달은 검증 문서에 남겼다. 태그/배포 단계 진행 중.
- Ruling: CPU 캡처 측정의 색상 Mock을 동일 반환값의 함수로 바꾼다. 120프레임 프로파일에서
  46,320회 Mock 호출이 0.719초를 쓰고 기록 객체를 누적했다. 색상 변환/픽셀 결과를 유지하며
  검사 도구의 기록 비용만 제거한다. 네이티브 출력 측정과 제품 품질 기준은 변경하지 않는다.
- Ruling: 128초 Windows 출력 검사에서 p95 12.521~77.254ms로 일부 테마가 목표를 넘었다.
  행 전체 전송 중 같은 속성 구간의 내용까지 이전 프레임과 같으면 전송을 생략한다.
  셀별로 쪼개는 전송 대신 기존 속성 구간을 보존한다. 넓은 문자/삭제/색상 변경/오류 복구와
  전체 프레임 동등성을 검사한 뒤 1회 재측정하고, 남은 출력 제한을 그대로 보고한다.
